## 0. 概述

| 交付物 | 代码位置 | 关键入口 |

| P1-1a 信号历史回填 | `engine/replay.py` | `scripts/backfill_signals.py` |

## 1. P1-1a 信号历史回填（确定性回放）

- **功能**：对已入库 K 线，用与扫描器完全相同的评估入口（`enrich` + `evaluate`）一次性补登历史信号，使台账/周报/看板覆盖"过去两周"乃至全历史。
- **幂等**：写入走 `insert_signal_if_new`，唯一索引 `uq_signal_dedupe (rule_id, symbol, contract_type, timeframe, ts, direction)` 去重；**不覆盖已推送行**（ON CONFLICT DO NOTHING），重复运行安全。
- **PIT**：atr14 按信号 bar 的 ts 精确取值（`atr_by_ts` 映射），价格区间 = 收盘价 ± 0.5×ATR。
- **用法**：`.venv/Scripts/python.exe backend/scripts/backfill_signals.py [SYMBOL]`（不传则全池）。
- **样本门槛**：窗口 < `WARMUP_BARS+2`（202）根时跳过并打印，不产生噪音信号。

## 2. P1-1b 模拟台账（S6，paper_position）

- **功能**：把 signal 表配对的 entry/exit 事件结算为模拟持仓，写入 `paper_position`；支持 open/closed 状态与最大不利偏移（MAE）。
- **成交口径（PIT）**：成交价 = 信号 bar 收盘价（=推送价，非看盘时刻价）。每笔名义本金与费用模型：

| 市场 | 名义本金 | 手续费 | 印花税 | 滑点 |
|------|----------|--------|--------|------|
| 币圈（okx） | 1000 USDT | taker 单边 0.05%（`FEES`） | 无 | 单边 5bps（`SLIP_BPS`） |
| A 股（akshare） | 10000 CNY（`NOTIONAL_A`） | 佣金万 2.5 单边、最低 5 元/笔（`COMM_A/MIN_COMM_A`） | 千 0.5 仅卖出（`STAMP_A`） | 单边 5bps |

- **幂等**：以入场 `signal_id` 为唯一键 upsert（`uq_paper_position_signal`）；`rebuild()` 可反复执行、结果一致。
- **性能**：价格视图用 numpy 数组 + TS 索引（`_Px`），全量 rebuild **< 1s**（修复 dict.setdefault 参数每次求值导致的 1103 次重复加载，提交 f98e191）。
- **用法**：`.venv/Scripts/python.exe backend/scripts/run_ledger.py`（打印 total/closed/open 概览）。
- **验证（verify_ledger.py）**：①回填/重建幂等；②**逐笔独立复算**（对原始 K 线重算 qty/费用/滑点/pnl，容差 1e-9；A 股分支用字面量口径独立复算）；③与 vectorbt 对照（执行位移方向性一致）。验证时点 2026-10-12：**1107 笔全量复算 0 不一致**（其中 A 股 2 笔）。

## 3. P1-2 周报（命中率/盈亏比 + 企微卡片）

- **功能**：按 `exit_ts` 窗口聚合已平仓持仓，输出总览 + 按周期 + 按标的的 笔数/胜率/盈亏比(PF=Σ盈/|Σ亏|)/均收益/累计盈亏（USDT）。
- **窗口**：`last_week_window` 恒为**上周一 00:00 ~ 本周一 00:00 UTC**；扫描器每周一 01:00 UTC 自动跑（`on_weekly`，`weekly_report` job）。日常查"过去 N 天"用 `--days N`。
- **推送**：企微 markdown 卡片（`render_markdown`，含口径注脚"taker 0.05% + 滑点 5bps 双边 · 模拟台账，非投资建议"）。
- **用法**：
  - 打印：`.venv/Scripts/python.exe backend/scripts/weekly_report.py --days 14`
  - 推送：加 `--push`（手动触发完整 w周报链路）。
- **验证（verify_report.py，离线 mock webhook）**：①SQL 独立复算与 `build_report` 全字段一致；②窗口边界恒为上周一→本周一；③空窗口不崩；④mock 端到端 push_log=sent；⑤业务错误 errcode 93000 → failed 不重试。

## 4. P1-3 事件驱动签发回测器（S5）

- **功能**：对指定规则逐 bar 事件驱动回放（与实盘扫描**同一 evaluate 入口**），输出逐笔交易 + 净值曲线 + 指标集；`--compare` 输出与研究层（vectorbt）对照。
- **成本模型**：与台账同源（`ledger.FEES/SLIP_BPS`，A 股规则同 A 股费率），非简化近似。
- **用法**：
  ```
  .venv/Scripts/python.exe backend/scripts/run_backtest_event.py \
      --rule sma_520_1m_BTC/USDT [--compare] [--out data/backtest_reports/event_xxx]
  ```
  `--out` 落盘 trades.csv / equity.csv / metrics.json（签发凭证，可复现）。
- **双层对照语义**：研究层（vectorbt 向量化）与研究层不一致处**如实标注**（如 1h chandelier 规则研究层明确 `vbt_error` 不可对照，不强行对齐）；1m 无 chandelier 规则验证"vbt 入场 > 事件入场"（cooldown 生效方向性）。
- **验证（verify_event_bt.py）——核心铁证**：①**事件驱动回放交易 == 实盘 paper_position 台账逐笔一致**（取 end=now-2min 避开未完结 bar，只比 exit_ts≤end 的已平仓）；②同规则两次运行逐笔一致（确定性）；③边界：恒假规则 0 事件、净值恒等于初始资金不崩。

## 5. P1-4 H5 看板（Next.js + AntD + lightweight-charts）

- **页面**（`frontend/app/`，响应式 H5）：

| 路由 | 功能 |
|------|------|
| `/`（台账报表） | 总览卡片（平仓笔数/胜率/盈亏比/累计）+ 按周期/按标的明细表 |
| `/chart` | K 线图（lightweight-charts）+ MA5/10/20 叠加 + 历史买卖点标记 + 标注按钮（采纳/忽略/看错）；5s 轮询自动刷新（含盘中未收盘蜡烛） |
| `/signals` | 信号历史表（pushed 计数、标注状态），按标的/周期过滤 |
| `/symbols` | 自选池列表（周期/规则数/last_ts）+ 搜索加币 |

- **API**（FastAPI，`/api/*`，每请求短连接）：

| 端点 | 说明 |
|------|------|
| `GET /api/health` | 存活检查 |
| `GET /api/report?days=14` | 台账报表（含 markdown 渲染文本） |
| `GET /api/positions?status=all\|closed\|open&limit=N` | 模拟持仓流水 |
| `GET /api/signals?symbol=&timeframe=&limit=&offset=` | 信号历史（含 pushed/annotation） |
| `GET /api/ohlcv?symbol=&timeframe=&limit=` | K 线 + MA5/10/20 + 信号 markers（多市场自动解析 exchange/contract_type）；`&live=1` 附 OKX 盘中 bar（仅展示不入库） |
| `GET /api/symbols` | 自选池（按 rule 表 enabled 聚合） |
| `GET /api/symbols/search?q=` | 标的实时搜索（ccxt load_markets，不入库） |
| `POST /api/symbols` | 自助加币（见 §6） |
| `POST /api/annotations` / `GET /api/annotations?signal_id=` | 标注回流（采纳/忽略/看错 + 笔记） |

- **启动**：
  - 后端：双击 `start_api.cmd`（uvicorn 127.0.0.1:8000，日志 `data/logs/api.log`）
  - 前端：`cd frontend && npm run dev`（3000）；生产 `npm run build && npm run start`
  - **注意**：`next dev` 与 `npm run build` 不能共存（`.next` 互踩导致 chunk 404），build 前先停 dev。
- **验证（verify_api.py，TestClient）**：health/report（SQL 独立复算一致）/positions/signals（pushed 计数与 push_log 一致）/ohlcv（markers 落于 bars 内、坏 symbol 404）/symbols/标注回流全链路（含 422/404 负例与测试行清理）。浏览器端到端已实测（K 线标注、加币、标注按钮）。

## 6. P1-5 标的搜索自助加币

- **搜索**：`GET /api/symbols/search?q=` —— ccxt `load_markets()` 实时过滤（USDT 现货），前缀优先排序，`in_pool` 标注已入池；不预存全量市场。
- **加币**：`POST /api/symbols {symbol, timeframes[]}`（timeframes ∈ 1m/1h/4h）全自动链路（**全部幂等**）：
  1. symbol 表 upsert（asset_class=crypto, contract_type=spot）
  2. 绑默认规则（`ensure_rules`）
  3. K 线回填（不足 `HISTORY_MIN_BARS=250` 根时按周期折算天数分页拉取）
  4. 历史信号回放（§1）+ 台账重建（§2）
  5. 扫描器**每 tick 重读规则与池**，≤1 个周期自动纳入采集，**无需重启**
- **1m 资格控制**：`core_from_rules` 决定 1m 仅核心池（配置 `SYMBOLS`）采集；自助币默认 1h/4h（可显式加 1m 进入核心资格逻辑）。
- **实测（2026-10-12）**：XRP/USDT 加币全链路 **2.0s** 返回（回填 564 根、回放 3 条信号）；搜索"已入池"disabled 正确；重复 POST 幂等。
- **验证（verify_symbols.py）**：搜索命中/大小写/前缀优先/乱串空；加币全链路 + 重复幂等；422/404 负例；`active_pool`/`core_from_rules`/`scan_tfs` 过滤行为；真实 1h tick 冒烟（数据新鲜度）。

## 7. P1-6 A 股扩标的（akshare）

- **范围**：日线（1d）全链路 —— 采集入库 → 规则评估 → 信号落库 → 台账（A 股费率）→ API/看板展示。起步池：`STOCK_SYMBOLS=000157.SZ,002284.SZ,600199.SH`（中联重科/亚太股份/金种子酒）。
- **数据源锁定（单源，禁止 fallback）**：`stock_zh_a_daily`（**新浪**），后复权 **hfq**。
  - 教训：东财 kline API 在本机被限频 RST 不可靠；且**东财与新浪 hfq 基准实测差 1.59 倍**（同 bar 000157：364.74 vs 579.63），跨源 fallback 会造成序列跳变（曾实测 +59% 跳变）+ 静默混源，**已删除东财代码路径**。
  - 单源 + 重试（3 次退避）；单日采集失败由扫描器"次日补评"语义兜底（见下）。
  - hfq 语义：**历史 bar 值不随新除权变化** → PIT 与幂等的前提（前复权不可用）。volume 由股归一为手（÷100）。
- **PIT**：bar ts = 所属交易日 **00:00 UTC**；可用时刻 = ts + 7h（= 15:00 CST 收盘，中国无夏令时）；未到可用时刻的 bar（盘中实时快照）**丢弃**，防收盘前入库破坏 PIT。
- **调度**：扫描器内 `scan_stock_1d` job，每日 **07:05:05 UTC**（= 15:05 CST，收盘后 5 分钟）；`scan_daily` 对**新到的全部 bar** 评估（非仅最新 1 根）→ 天然"次日补评"：某日采集中断，次日 tick 会把缺口 bar 一并评估补登。
- **规则模板**：日线 `sma5_cross_sma20`（entry cross_up / exit cross_down，cooldown=2）。
- **历史回填**：`ensure_stock_history` 在样本 < 250 根时回填最近 500 自然日 + `replay.backfill` 补登历史信号。
- **验证（verify_stock.py，六段）**：①数据完整性（≥250 根、ts 对齐 00:00 UTC、最新 bar 已收盘且未滞后）；②复权对照（hfq vs raw ratio>1.5，网络失败 SKIP）；③信号确定性复算（evaluate 全窗口与 signal 表双向集合相等）；④台账逐笔独立复算（字面量口径）+ 配对计数；⑤API 多市场兼容（/api/ohlcv A 股标记、/api/symbols、/api/report）；⑥`scan_daily` 冒烟（不产生晚于最近已收盘 bar 的信号）。
- **验证时点数据（2026-10-12）**：三票各约 330 根，最新 2026-10-09；金种子酒 4 个信号与改源前时点完全一致（EMA 交叉对常数缩放不变的换源自检）。

- 推送覆盖：1m 仅核心池，1h/4h 全池；实测约 75 条/天（97% 来自 1m）。
