## 0. 概述

P2 目标（计划）：在技术面规则信号之上叠加**智能研判增强** —— 资金面/信息面投票、AI 研判理由、读图第二意见，飞书为第二推送通道。

| 交付物 | 代码位置 | 关键入口 |
|--------|----------|----------|
| P2-1 资金面算子 | `engine/flow.py` + `scanner.collect_flow` | 扫描器 `flow_collect` job（15min） |
| P2-2 LLM 网关 | `adapters/llm/gateway.py` | `gateway.complete(task, …)` |
| P2-3 A1 信息挖掘 | `adapters/news/rss.py` + `engine/news.py` | 扫描器 `news_collect` job（10min） |
| P2-4 S7 三票合议 | `engine/votes.py` | `_evaluate_trigger` 内 `votes.compute/save` |
| P2-5 A4 解释文案 | `engine/explain.py` | `run_scanner._hook` |
| P2-6 A2 读图票 | `engine/chart_vote.py` | `run_scanner._hook` |
| P2-7 飞书适配器 | `adapters/notify/feishu.py` | `_hook` / `_weekly` 多通道扇出 |
| P2-8 信息票回测 | `engine/news_backtest.py` | `scripts/run_news_backtest.py --days 30` |

核心决策：**增强不拦** —— 三票分数、读图票与 AI 理由如实落库并附推送，不拦截任何信号（先积累数据，是否启用门槛另行评估）。

推送链路（`run_scanner._hook`）：信号生成 → 三票 `votes.compute` 落库 → `explain.build_reason`（≤200 字）→ `chart_vote.render_chart` + `run`（与推送共用同一张截图）→ 企微/飞书按配置扇出。

## 1. P2-1 资金面算子（funding / OI，asof PIT）

- **表**：`funding_rate`（OKX 永续 8h 结算点）、`open_interest`（OI 采样；唯一键幂等 do nothing）。
- **算子**（DSL 叶子列，`flow.attach`）：
  - `funding_rate`：bar ts 取 "≤ ts 的最新已结算值"（merge_asof backward）。
  - `oi_change_24h` = asof(ts) / asof(ts−24h) − 1；任一端无值 → NaN（比较不触发）。
- **PIT**：对齐只用 ts ≤ 当前 bar 的数据；序列起点之前的 bar 为 NaN；截断前缀一致性已验证（verify_flow ④）。
- **永续服务现货**：资金面天然属永续，表内 symbol 用内部规范串 —— 现货信号取同 base 永续序列作市场情绪代理；A 股无资金面（缺席票，见 §4）。
- **三态同源**：实时扫描 / 历史回放 / 签发回测均经 `attach_if_needed` 注入（仅规则 DSL 引用列时读库），保证信号一致。
- **采集**：`collect_flow` 每 15min（funding 近 5 点 + OI 当前采样）；启动时 `ensure_flow_history` 回填 30 天（缺失或落后 >1 天触发）。
- **验证（verify_flow.py）**：①采集冒烟（网络不可用 SKIP）；②数据语义（结算整点、OI 严格递增）；③asof 独立 bisect 复算逐根一致；④PIT 无未来函数；⑤DSL 方向性（恒假 → 0 事件；恒真不改事件集）。

## 2. P2-2 LLM 网关（LiteLLM + 百炼 OpenAI 兼容）

- **档位**（.env 可配，逗号分隔 = 回退链）：`extract`（信息结构化）/ `explain`（解释文案）/ `vision`（读图票，多模态）。
- **调用**：litellm `openai/` 前缀 + `api_base` = 百炼 compatible-mode；`json_mode` → `response_format=json_object`；返回 `LlmResult(text, model)`（实际成功模型，供落库溯源）；全链失败抛 `LlmError`；key 为空快速失败不发请求。
- **思考链默认关闭**（提交 26cede5）：`complete()` 默传 `extra_body={"enable_thinking": False}`（调用方 kw 可覆盖）。原因：qwen3 系思考型模型不关思考会先输出数千 token 推理链，实测单次延迟 1.4~92s 方差极大（30s 超时下失败率高）；关闭后实测 1~3s。兼容非思考模型（qwen-plus 实测可用）。
- **启动优化**：`LITELLM_LOCAL_MODEL_COST_MAP=True` 跳过远端价格表（GitHub raw 不可达时避免重试阻塞）。
- **实测模型（2026-10-12，.env 配置）**：三档位统一 `qwen3.7-flash-2026-07-15`（支持视觉）；`qwen-vl-max` 在百炼该账号返回 `Model not exist`（已弃用）。
- **失败语义**：所有调用方按"降级不阻塞"处理 —— 解释/读图失败 → 纯信号推送；结构化传输失败 → 下轮重试。注意 SDK 内建 `max_retries=2`（超时失败总耗时 ≈3×timeout）。
- **验证（verify_gateway.py）**：①回退链序列 ②全链失败 LlmError ③空 key 快速失败 ④档位映射与参数透传 ⑤真实调用（1.0s）。

## 3. P2-3 A1 信息挖掘（RSS → news_raw → news_event）

- **源**（2026-10-12 实测直连可用）：panews（中文快讯）/ coindesk / cointelegraph / theblock；Odaily/BlockBeats RSS 已下线未纳入。单源每路由最多 2 次，直连失败且配置代理时改走代理。
- **入库**：`news_raw` 按 url 去重；HTML 清洗 + 截断（title 300 / summary 500）；无链接或无发布时间条目跳过。
- **PIT**：仅结构化 `published_ts` 非空且 ≤ now 的条目；事件时间基准 = 原文 published_ts（非抓取时间）。
- **结构化**：system prompt 强制 JSON schema；字段钳制 —— symbols 大写正则、event_type 9 类枚举（etf/regulation/exchange/security/listing/project/whale/macro/other）、sentiment ∈[-1,1]、magnitude/confidence ∈[0,1]、impact_dir（缺失按 sentiment 推断）；正文指令性文字视为待分析数据（注入防护），LLM 不参与推送决策。
- **失败语义**：单源抓取失败跳过；LLM 传输失败该条不置 processed（下轮重试）；非法 JSON 记 0 事件并置位（防同条无限重试烧配额）。
- **调度**：扫描器 `news_collect` job 每 10min：采集 + 结构化（每轮上限 10 条，`NEWS_EXTRACT_LIMIT`）；未配置 LLM_API_KEY 仅采集。
- **落库**：`news_event`（extracted_by_model 记录实际模型）。实测（2026-10-12）：单条 1.4~2.2s；"香港将上市第二只现货 Solana ETF" → SOL etf/bullish、"某交易员 STONK 仓位" → STONK whale/bullish，语义正确。
- **验证（verify_news.py，六段）**：RSS 冒烟 / 去重 / PIT / 解析单测 / DB 管道隔离（含失败不置位）/ 真实 LLM 结构化。

## 4. P2-4 S7 三票合议（tech / flow / info）

- **票语义**：strength ∈ [0,1] = 对"信号方向"的支持度（0.5 中性）。
- **技术票**（0.5 起）：价格与 EMA60 同侧 +0.2；RSI 有利区 +0.15 / 过狂热 −0.2 / 逆向极端 −0.1（多空阈值不同）；量比 ≥1.2 +0.15 / <0.8 −0.1。
- **资金面票**（0.5 起，按在场分量归一）：funding 反向拥挤 ±0.3（|0.05%/8h| 满档，−fr 支持多头）；OI24h ±0.2（|5%| 满档，方向无关：新仓进场增强 / 平仓退潮减弱）。
- **信息票**：72h 窗口内事件按 24h 半衰期加权平均 `sent×mag×conf`，±0.5 映射支持度。
- **缺席票**：数据不可得（A 股无资金面、窗口无事件、bar 不在指标窗口）→ strength=None，evidence 记原因；`total` = 在场票按权重 tech 0.4 / flow 0.35 / info 0.25 加权平均（全缺席 → None）。
- **落库**：`signal` 四分数（tech/flow/info/total）+ `signal_vote` 每票一行（strength + evidence_json 全量特征，供审计与迭代）。
- **PIT**：信息票仅聚合 published_ts ≤ 信号 ts；资金面 asof ≤ ts。
- **验证（verify_votes.py，六段）**：技术票确定性/方向性；资金面 asof 独立复算（不复用 flow 实现）；信息票 PIT + 半衰期分数；端到端落库（total 独立复算）；A 股缺席票语义；清理合成数据。

## 5. P2-5 A4 信号解释文案

- **功能**：信号上下文（标的/价格/规则 + 三票明细含缺席原因）→ LLM 输出 ≤200 字中文研判理由（强制 JSON `{"reason"}`）。
- **定位**：只解释已有信号，不参与是否推送的决策；理由为展示层字段（不落库），追加到推送卡片 "AI 研判" 行。
- **幻觉防护**：后置正则过滤违禁表述（保证/必涨/必跌/稳赚/包赚/无风险/一定会/100%/百分百/必定/梭哈/重仓）→ 命中即降级。
- **失败降级**：LLM 不可用 / 输出非法 / 空 / 违禁 → 返回 None → 推送回落纯信号版（不阻塞）。
- **超时**：30s（思考链关闭后实测 3.4s）。
- **验证（verify_explain.py，七段）**：mock 合法输出 / 超长截断 200 / 违禁拒绝 / 非法与传输失败降级 / 空 key 降级（SKIP）/ 卡片渲染断言（含溯源行）/ 真实 LLM 段。

## 6. P2-6 A2 多模态读图票

- **功能**：把信号 K 线截图（含 EMA20/60 + 成交量）交给视觉模型做第二意见 → `signal_vote(vote_type='chart')`。
- **共用一张图**：`render_chart` 复用推送截图路径（`data/charts/signal_{id}.png`，600 根窗）；企微推送以 sentinel（`_AUTO`）区分"内部渲染/外部产物"，读图与推送严格共用同一产物。
- **映射**：agree → 0.5+0.5×confidence；oppose → 0.5−0.5×confidence；neutral → 0.5；strength 钳制 [0,1]、非法 stance 归 neutral、非 dict JSON 保护。
- **失败降级**：渲染/传输/解析任一失败 → None（不阻塞推送）。
- **验证（verify_chart_vote.py，九段）**：mock 映射 / 钳制与容错 / fence 解析 / 失败降级（含图不存在）/ 真实渲染冒烟 / 落库端到端与清理 / 卡片读图行 / `_hook` 编排全链路 / 真实 vision 读图（1.8s）。

## 7. P2-7 飞书推送适配器（第二通道）

- **形态**：interactive 卡片 + lark_md（飞书无 "> " 引用语法 → 加粗标签版式：`**三票**/**读图**/**溯源**/**AI 研判**`）。
- **签名**：配置 `FEISHU_SECRET` 时附 `timestamp + sign`（HMAC-SHA256：`base64(hmac_sha256(key=f"{ts}\n{secret}", msg=""))`）；未配置则不附。
- **可靠性**：业务错误（errcode≠0）→ 失败不重试；网络错误 → 退避重试（最多 2 次）；push_log 复用（channel 区分通道）。
- **多通道扇出**：`_hook` / `_weekly` 对企微与飞书独立开关（webhook 配了才发）；周报同双通道。
- **边界**：飞书图片消息需应用 token 上传（未做）→ 飞书仅卡片文本，截图仍走企微。
- **现状**：`FEISHU_WEBHOOK` 尚未配置 —— 代码经 mock 服务器全链路验证（verify_feishu 六段），真实推送待 webhook 填入后由扫描器触发。

## 8. P2-8 信息票独立回测（IC / 命中率）

- **PIT entry**：发布后第一根"close 时刻严格晚于发布时间"的 1h bar（`bisect_right(ts, published−1h)`）—— 发布恰在 bar 开盘 / bar 内 / bar 收盘（=下根开盘）三种边界均不含未来。
- **窗口收益**：r_W = entry 后满 W 小时的第一根 close / entry close − 1（W ∈ {1h, 4h, 24h}；数据不足 None）。
- **样本**：事件 × 可匹配行情的符号（base 匹配现货 1h 序列，缺失回退永续）；score = sent×mag×conf（与 info_vote 同口径）。
- **指标**：IC = pooled Spearman(score, r_W)（n≥3，方差 0 → None）；命中率 = impact_dir 与 r_W 方向一致占比（bullish→r>0）。
- **报告**：按窗口 IC/命中、按方向（24h）、按类型（24h，n≥3）；markdown 落 `data/backtest_reports/news_ic_YYYYMMDD.md`。
- **用法**：`.venv/Scripts/python.exe backend/scripts/run_news_backtest.py --days 30`
- **验证（verify_news_bt.py，七段）**：PIT entry 三边界 / 收益独立复算 / IC 数学性质（单调→1、逆序→−1、n<3→None）/ 命中率构造 / 多符号展开 / 报告渲染 / 清理。

## 14. 已知边界与后续

- 飞书真实推送待 webhook（当前仅 mock 验证）。
- 回测样本需积累：IC/命中率 n<3 显示 "—"；24h 窗口需发布后满一天。
- 资讯源可用性依赖上游 RSS（历史曾下线 Odaily/BlockBeats）；直连失败自动走代理。
- `qwen3.7-flash-2026-07-15` 为带日期快照名，到期需在 .env 换新模型（网关默认关思考链，换型即用）。
- A 股无资金面/信息票（缺席语义已覆盖），读图/解释对 A 股照常生效。
- **离线回填路径无"仅已收盘"过滤（待修）**：`backfill.py` / `scanner.ensure_history` / `routes.py` 加币回填会写入当日未收盘 bar；2026-10-12 实测发现并清理 22 行 okx 1d（ts=10-12 未收盘），根因是这三条路径直接 upsert 拉取结果，而实时 `scan()` 有 `r[0] <= trigger` 过滤。修复方案为三处各加一行同样过滤，待确认后实施。
- 资讯积压消化速率受"每轮 10 条"上限约束（重启后 171 条待结构化 ≈ 2.9h 清空），如需提速可调 `scanner.py` 上限。
