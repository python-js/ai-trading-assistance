## 3. ccxt(OKX) 采集适配器设计

### 3.1 symbol 规范与映射
- ccxt exchange id：`okx`。
- **现货**：ccxt symbol `BTC/USDT` → 内部 `(base=BTC, quote=USDT, contract_type=spot)`。
- **永续(swap)**：ccxt symbol `BTC/USDT:USDT` → 内部 `(base=BTC, quote=USDT, contract_type=perp)`。
- 适配器负责 ccxt symbol ↔ 内部三元组互转；入库统一用内部规范，`symbol` 表存 `exchange_symbol`（ccxt 原串）便于回放。
- 初始自选池：BTC、ETH、ONDO + 市值 TOP（`fetch_tickers` 按 quoteVolume 排序取 Top N，N 可配）。

### 3.2 采集内容与接口（ccxt 统一方法）
| 数据 | ccxt 方法 | 适用 | 频率 |
|------|-----------|------|------|
| K线 OHLCV | `fetch_ohlcv(symbol, timeframe, since)` | 现货+永续 | 每 timeframe 收盘后拉增量 |
| 资金费率 | `fetch_funding_rate` / `fetch_funding_rate_history` | 仅永续 | 每分钟/每结算周期 |
| 持仓量 OI | `fetch_open_interest` / `fetch_open_interest_history` | 仅永续 | 每分钟 |
| 爆仓/强平 | ~~`fetch_liquidations`~~ **实测 ccxt okx 抛 NotSupported**；资金面票 P0 改用 资金费率+持仓量+成交量，爆仓降级见 §6 | 仅永续 | **P1**（P0 不采）|
| 订单簿快照 | `fetch_order_book`（采样） | 现货+永续 | **P1**（签发回测滑点建模用），P0 不采 |
| 全市场列表 | `load_markets()` / `fetch_tickers()` | — | 标的搜索/市值 TOP |

- timeframes（P0）：`1m`（分钟扫描）、`1h`、`4h`（主信号）、`1d`（趋势过滤）。

### 3.3 增量与回填
- **回填**：首次 `fetch_ohlcv(since=起始)` 分页拉全历史（**实测单页上限 300 根**，limit>300 仍只返回 300；分页递进 since），upsert 去重入库。
- **增量**：`since = max(ts)+1`（该 symbol/tf 最后一条），只拉新 bar；upsert `on conflict do nothing`。
- **缺口检测**：相邻 bar 间隔 > timeframe → 记缺口告警并触发补拉（保证 PIT 与回测连续）。

### 3.4 限频与退避
- OKX 公共接口按 IP 限频（**实测 ccxt `rateLimit=110ms` ≈ 9 req/s，`enableRateLimit=True` 已自动节流**）。设计：进程内**令牌桶**限速 + 失败**指数退避**重试 + 多 API key 轮转（key 仅提升私有/部分公共额度；公共行情主要靠退避）。多节点/多 IP 轮换为 P1。
- 调度对齐：每 timeframe 的拉取任务在 **bar 收盘后 +2~5s 缓冲**触发，避免拉到未收盘 bar（PIT）。

### 3.5 适配器接口草案（伪代码，非实现）
```
interface MarketAdapter:
    list_markets() -> Market[]                       # 含 spot/perp 标记
    search(q) -> Market[]                            # 供 /api/symbols/search
    fetch_ohlcv(internal_symbol, timeframe, since) -> DataFrame
    fetch_funding(internal_symbol, since) -> DataFrame        # perp only
    fetch_open_interest(internal_symbol, since) -> DataFrame  # perp only
    fetch_liquidations(internal_symbol, since) -> DataFrame   # perp only, 可降级
    server_time() -> ts                              # 对齐交易所时钟
class OKXAdapter(MarketAdapter): ...                 # P0 唯一实现
# 未来 BinanceAdapter 同接口替换，业务层无感（主方案原则5）
```

## 4. P0 接口定义草案（请求/响应 schema 概要）

> 仅 schema 概要；字段类型实施时以 Pydantic 模型落地。

- `GET /api/symbols/search?q=btc`
  → `{ items: [{ symbol, exchange, contract_type, base, quote, exchange_symbol, quote_volume_24h }] }`（ccxt 实时，不入库）
- `POST /api/symbols` `{ symbol, exchange, contract_type, timeframes[] }` → 创建自选并触发回填任务
- `GET /api/ohlcv?symbol=&contract_type=&timeframe=&from=&to=`
  → `{ bars: [{ ts, open, high, low, close, volume }] }`
- `GET/POST/PUT/DELETE /api/rules`；`POST /api/rules/{id}/toggle`
  rule body 含主方案 9.1 DSL（entry/exit/vote/cooldown/cost_model）
- `GET /api/signals?passed=&symbol=&from=&to=`；`GET /api/signals/{id}`（含 `votes[]` 逐票）
- `POST /api/backtests` `{ rule_id, from, to, timeframe, params?, benchmark }` → `{ task_id }`（BackgroundTasks）
  `GET /api/backtests/{task_id}` → `{ status, progress }`
  `GET /api/backtests/{task_id}/report` → 11 分区结构（9.3）
- `POST /api/notify/test` `{ channel: wecom|feishu }` → `{ ok, error? }`

## 6. 实测结论与剩余待验证项

### 6.1 已实测（2026-10-10，scripts/probe_okx.py，经代理 127.0.0.1:7897）
- **限频**：ccxt `rateLimit=110ms`（≈9 req/s），`enableRateLimit=True` 自动节流。
- **ohlcv**：单页上限 **300 根**；timeframes 支持 1m/3m/5m/15m/30m/1h/2h/4h/6h/12h/1d/1w/1M/3M；`since=90天前` 可回填（分页递进 since）。
- **symbol**：BTC/ETH/ONDO 现货(`X/USDT`)+永续(`X/USDT:USDT`) 6 个全部可加载。
- **资金费率**：`fetchFundingRate` / `fetchFundingRates` / `fetchFundingRateHistory` 均 `has=True`，实测返回正常。
- **持仓量**：`fetchOpenInterest` / `fetchOpenInterestHistory` 均 `has=True`，返回 amount+value。
- **爆仓**：`has.fetchLiquidations=None`，调用抛 `NotSupported: okx fetchLiquidations() is not supported yet`。ccxt 未封装 OKX 爆仓。
- **pgvector+timescaledb**：同镜像 `timescale/timescaledb:latest-pg16` 已确认共存（timescaledb 2.30.2 + vector 0.8.1），P0-1 已建库验证通过。
- **funding_rate_history**：8h 粒度（结算周期），30 天约 90 条，单次 `limit=1000` 可取全，无需分页。
- **open_interest_history**：1h 粒度单页上限 **100**（30 天 720 条需分页）；1d 单次可取；**5m 返回空（不支持）**。资金面票采用 funding(8h)+OI(1h)。
- **P0-2 回填实测（30 天）**：ohlcv 24 组合共 **264,801 行零缺口**；funding_rate 357 行；open_interest 2,160 行。
- **P0-3 指标验证（BTC/USDT 1h 720 根，verify_indicators.py）**：EMA20/60 与标准 `ewm(span,adjust=False)` **全程 0 差**；RSI14/ATR14 用 ta 库（Wilder RMA，`ewm(alpha=1/n,adjust=False)`），末值与标准一致，仅 warmup 种子暂态差：RSI `[50-100)=8.5→[100-200)=0.22→[200+)=0`、ATR `[50-100)=3.2→[100-200)=0.08→[200+)=0`。**硬约束：回测与实盘信号必须丢弃前 ≥200 根（≥3×最大 window）预热期**，否则暂态污染 RSI/ATR 阈值判断。
- **P0-4 DSL 评估验证（verify_dsl.py）**：逐 bar 事件式评估器（PIT、cooldown 内置）。① ema_cross 与向量化交叉掩码**逐事件严格一致**（强校验通过）；② 组合规则（金叉+RSI过滤+chandelier出场+cooldown=6）逐事件条件/冷却独立复核通过；③ 唐奇安突破首个入场点与参考一致；④ 解析器对算子拼写/非法位置/结构错误均报错不放行。资金面算子（funding/OI，asof PIT 对齐）为 P0-4b。
- **P0-5 回测验证（run_backtest.py，vectorbt 1.0.0）**：365 天 1h（8760 根）BTC/ETH/ONDO。成本 taker 0.05%+滑点 5bps；walk-forward 训练 720 根/样本外 168 根/步进 168 根共 **47 折**；输出 11 分区报告（`data/backtest_reports/`）+ 收益概述指标集（胜率/盈亏比/回撤/Sharpe/Sortino/Calmar/VaR/CVaR/成本占比）+ 样本外曲线。**固定种子两次运行 metrics+walkforward 哈希一致（PASS）**。诚实结论：裸 ema20_60 交叉在该年三标的全亏（-18%/-39%/-36%，基准 -24%/-33%/-28%），IS 均值 Sharpe +0.25 → OOS -2.75（衰减比 -11.0）——研究层如实暴露过拟合，不美化。环境注记：vectorbt 1.1.x 强制 pandas≥3（弃用），采用 **vectorbt 1.0.0 + pandas 2.3.3 + plotly<7**（plotly 7 移除 scattermapbox 致导入失败）。
- **P0-6 扫描验证（run_scanner.py）**：自选池 = 配置 3 标的 + 市值 TOP5（quoteVolume，实测 STRK/SOL/NEAR 等入选）；规则种子 15 条（全池 4h 交叉 + 1h 交叉/RSI 过滤/chandelier 出场 + 核心池 1m，cooldown 2/6/30）。① `--once` 冒烟通过：历史自检按周期回填（4h 276 根=46 天、1d 271 根=271 天），1m 停更 35h 经分页一次追平；② **live 模式各周期 bar 收盘 +3s 触发，单次扫描 ~2s 完成（"新 bar 后 <60s 触发评估"满足）**；③ 心跳 60s 输出，实测"停更: 无"；④ 信号落库接线与唯一索引去重实测通过（同事件二次插入被拒）；⑤ 停机跨多根只评估最后一根（`trigger > max(ts)` 守卫），重启不补推洪峰。实施中修正两缺陷：心跳连接泄漏（改短连接）、1m 增量 300 根/轮追平过慢（改分页一次追平，正常态仍 1 请求）。
- **P0-7 出图验证（verify_chart.py → data/charts/verify_btc_1h.png）**：mplfinance 蜡烛 + EMA20/60 叠加 + 买卖点标记（entry 绿▲/exit 红▼ 标于事件 bar 低/高点外侧）+ 最近信号价格区间虚线（自信号 bar 向右延伸，避免全幅横线误读为支撑位）。BTC/USDT 1h 600 根窗口实测：全程 7 事件、图窗 2 事件（10-07 死叉▼ 84388、10-10 金叉▲ 83031.2），**事件 ts 与 bar 对齐断言 PASS（无静默丢标），可视复核落点正确**。注记：mplfinance style 会重置字体，中文须经 `make_mpf_style(rc={"font.sans-serif"})` 注入，否则方块字。
- **P0-8 推送离线验证（verify_notify.py，本地 mock webhook）**：一条信号 = markdown 文本 + image 截图（base64+md5，实测 39KB PNG 编解码一致）。① payload 结构与图片完整性 PASS；② 业务错误（errcode 93000）不重试、push_log=failed；③ 网络错误退避重试（断开→1s 后重试成功，attempts=3）；④ push_log sent/failed 落库正确。**真实手机推送已验收（2026-10-12 10:51 北京，replay_signal.py 回放 ema_2060_1m_BTC/USDT @02:17 UTC 事件，signal_id=3，push_log=sent，手机收到文本+截图，M1 达成）**。设计说明：企微 template_card 图文卡片要求图片公网 URL，本地场景不可用，故采用"文本+图片"两条消息；飞书适配器不在 P0 范围。推送价 = 触发 bar 收盘价（PIT 纪律），非推送时刻实时价。

### 6.2 爆仓数据降级方案（待你确认）
ccxt 拿不到 OKX 爆仓，三票的"资金面票"处理建议（**P0 采用 A，爆仓整体推迟到 P1**）：
- **A（P0 推荐）**：资金面票 = 资金费率 + 持仓量(OI)变化 + 成交量放大，**不含爆仓**。已实测全部可用，零额外依赖。
- **B（P1 可选）**：直连 OKX 原生 REST `/api/v5/public/liquidation-orders`（ccxt 未封装，需自己发请求）；注意 OKX 该端点返回的公共强平数据本身较有限。
- **C（P1 可选）**：第三方爆仓聚合（Coinglass 等），需 API key/可能付费。
