## 0. 概述

P3 目标（计划）：**A5 个人研判知识库** —— 让推送理由引用本人历史复盘经验（RAG）；**A3 策略生成** —— 把中文交易想法变成可沙箱回测、可人工启用的一条规则草稿。

| 交付物 | 代码位置 | 关键入口 |
|--------|----------|----------|
| P3-0 遗留修复 | `adapters/market/ccxt_okx.py`、`scanner.ensure_history`、`routes.py`、`scripts/backfill.py` | 启动/回填路径 |
| P3-1 A5 后端 | `engine/rag.py` + `gateway.embed` + `explain` 注入 + `/api/knowledge` | `run_scanner._hook` / API |
| P3-2 A5 前端 | `app/knowledge/page.tsx` + 信号页标注笔记输入 | 导航"知识库" |
| P3-3 A3 后端 | `engine/rule_gen.py` + `/api/rules*` + 沙箱回测 | `/api/rules/draft` |
| P3-4 A3 前端 | `app/strategy/page.tsx` | 导航"策略" |

核心决策：**人工语料**（AI 生成的理由不入库，避免自我循环）；**草稿人审**（生成即 enabled=false，开关即审核）；**同步沙箱**（秒级事件驱动回测，只算不写不推送）。

知识链路（推送时）：信号生成 → `rag.recall`（K=3 语义召回，失败静默 []）→ `explain.build_reason` 注入"本人历史研判参考"段 → 推送卡片 AI 研判行。
生成链路（人用）：中文想法 + 标的/周期 → `rule_gen.generate`（LLM 生成 → 校验 → 失败回喂重试一次）→ 草稿入库（enabled=false）→ 沙箱回测 → 人审启用。

## 2. P3-1 A5 个人研判知识库后端

- **表**：`knowledge_chunk`（pgvector；`source_type`/`text`/`embedding`/`meta_json`/`created_ts`；镜像无 pgvector 扩展时跳过建表）。
- **向量化**：`gateway.embed` 走嵌入档回退链（默认 `text-embedding-v4`,`text-embedding-v3`，均 1024 维）；全链失败抛 `LlmError`。
- **入库**：`rag.add_chunk`（embed + insert）；来源 `manual`（手动条目）/ `note`（标注笔记）。
- **召回**：`rag.recall` 以信号上下文（`symbol timeframe 买入/卖出 rule`）embed 查询 → 余弦相似 top-3；**任何异常（LLM/DB）静默返回 []**，不阻塞推送。
- **注入**：`explain.build_reason` 收到 `s["knowledge"]` 时在 prompt 追加"本人历史研判参考"段（逐条原文）；无知识不含该段。
- **标注笔记自动入库**：`POST /api/annotations` 带非空 note → 组装 `[BTC/USDT 1m 买入] 标注「采纳」：<原文>` 向量化入库（source_type=note，meta={signal_id, action}）；入库失败仅告警，不阻塞标注本体。
- **API**：`POST /api/knowledge`（201；空文本/超 2000 字 422；LLM 不可用 503）、`GET /api/knowledge`（limit 1~500 / offset）、`DELETE /api/knowledge/{id}`（不存在 404）。
- **验证（verify_knowledge.py，六段 22 项）**：①embed 网关（真实 1024 维 / mock 全链失败→LlmError）；②入库-召回闭环（相关条目排第一、embedding 落库）；③explain 注入断言（含段与原文 / 无知识不含）；④降级不阻塞（recall 失败→[]、仍正常出理由）；⑤API 边界（422/404）；⑥标注 note 自动入库（带 note→入库、空→不入库、清理）。

## 4. P3-3 A3 后端（生成 / 校验 / 重试 / 规则 API / 沙箱回测）

- **生成**：`rule_gen.generate(text, symbol, timeframe)` —— 模型（explain 档 qwen3.7-flash，json_mode，timeout 30s）**只输出** `{entry, exit, cooldown_bars}`；`name/symbol/timeframe` 由服务端组装（防改写标的）。
- **校验**：`parse_rule`（结构）+ 列白名单 `COLS`（ema20/ema60/rsi14/atr14/close/high/low/funding_rate/oi_change_24h）——防虚构指标名等到回测才报错。
- **回喂重试**：校验失败把出错原文与原因回喂 LLM 重试一次；再失败抛 `RuleGenError` → API 422；`LlmError` → 503。
- **prompt 防错**：完整示例（RSI 30/70）+ 反例（禁止 `{"<": {"rsi14": 30}}` 算子在外）。实测 qwen3.7-flash 无示例时连续输出算子反转格式，加示例后连续 2 次真实调用均正确。
- **规则 API**：`POST /api/rules/draft`（201；text ≤500 否则 422；标的/周期无数据 404；无鉴权仅本机）→ 草稿 `name=gen_{symbol}_{tf}_{ms}`、INSERT enabled=false；`GET /api/rules`（limit 1~500）；`POST /api/rules/{id}/toggle`（404）；`POST /api/rules/{id}/backtest?days=`（默认 120，5~730；404；缺列 422）。
- **草稿语义**：与种子 `upsert_rule` 独立（种子 upsert 会置 enabled=true；草稿仅 INSERT false）；启用=人审开关。
- **沙箱回测**：`backtest_event.run_rule` —— 与台账**完全同口径**（信号 bar 收盘价成交 PIT、cooldown/状态机保真、taker 单边 0.05% + 滑点单边 5bps、每笔名义 1000 USDT 固定不复利）；**同步秒级、只算不写**（不落库、不推送、不改台账）；返回 metrics（笔数/胜率/盈亏比/累计/收益率/最大回撤/费用/平均持仓/暴露）+ trades（ts 转 ISO）+ open_pos + n_events。
- **验证（verify_rules_api.py，九段 25 项）**：列表含种子规则 / mock 回喂重试 2 轮（第 2 轮 prompt 含"校验失败"）/ 恒非法 422 不增行 / 未支持指标 422 / 无数据 404 且零 LLM 调用 / 真实 LLM 生成 201+parse_rule 通过 / toggle 与 DB 一致 / 沙箱回测（mock 草稿 30 天 3 笔 + 缺列 422 + 不存在 404）/ gen_* 清理。

## 5. P3-4 A3 前端策略页

## 10. 已知边界与后续

- **知识语料人工维护**：空库时召回 []、explain 无知识段照常出理由；AI 理由不自动沉淀（防自我循环，如需可另行评估）。
- **embed 档一致性**：v4/v3 均 1024 维按可互换设计（回退链透明）；若换入非 1024 维模型需重建知识库。
- **生成草稿不自动回测/启用**（人审设计）；`cooldown_bars` 提示常用 0~30。
- **沙箱深度受存量约束**：1m 现存 ≈32 天（4.6 万根）；`days=120` 对 1m 实际只回测存量部分（接口如实按 window 取数）。
- **pgvector 依赖**：镜像无扩展时知识表跳过建库（知识功能整体不可用；当前镜像已含）。
- **verify_api 与 note 联动的残留清理已补**：P3-1 起标注 note 自动入库，verify_api 的测试笔记会产生知识行，脚本已同步清理（回归时发现 1 条残留并清除）。
