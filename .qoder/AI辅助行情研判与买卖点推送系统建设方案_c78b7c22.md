# AI 辅助行情研判与买卖点推送系统 建设方案

**版本**:v1.0(2026-10-10) | **适用对象**:个人/小团队自建 | **参考样本**:BitSoul 量化策略 AI 助手(aicodingyard.com/quant,2026-10-10 实测逆向)

---

## 1. 方案摘要

构建一套面向**指定股票代码与虚拟币标的**的"信息挖掘 + 技术信号 + AI 辅助研判 + 买卖点推送"个人量化研判系统。核心思路:**可回测的规则引擎负责产生买卖点,大模型负责信息理解、研判解释与策略生成,模拟台账负责度量效果,推送渠道负责触达**。系统终点停在"推送提示",不接实盘下单。P0 阶段单人 2-3 周可用开源栈跑通最小闭环,首年现金成本可控制在千元级(云服务 + LLM API)。

## 2. 背景与要解决的问题

用户的四个需求本质是一个"研究→决策→执行提醒"闭环:

| 需求 | 当前痛点 | 系统对应能力 |
|------|---------|-------------|
| ① 指定股票代码/虚拟币的行业信息挖掘 | 资讯分散在公告、研报、媒体、社区,人工阅读吞吐低 | 多源抓取 + LLM 结构化提取(事件/情绪/关联标的/影响方向) |
| ② 策略 + K线走势判断买卖点位 | 主观看图不稳定、无法沉淀、无法验证 | 指标/形态规则引擎 + 可回测的参数化策略 |
| ③ 接入 AI 辅助研判行情 | LLM 直接预测价格不可靠 | AI 做"三票制"中的一票 + 信号解释 + 多模态读图 + 策略生成 |
| ④ 买卖点位推送通知 | 盯盘耗时、错过时机 | 调度器分钟级扫描 + 消息卡片推送到 IM |

参考 BitSoul 系统的原因:它已验证了同样的链路(监控规则/调度/模拟台账/研报抓取/知识库召回/多模型路由)在工程上成立,但它是企业私有化的重方案;本方案取其**工程模式**,砍掉企业级配置,用开源组件在 1/10 的成本内重建。

## 3. 建设目标(可检查)

1. 对自选标的池(≥10 个:A股 + 虚拟币)实现 7×24 行情与资讯自动采集,数据延迟 < 5 分钟(币)/ 当日收盘后(T+1 类 A股数据)。
2. 至少 3 个可复现的技术策略完成回测,输出胜率、盈亏比、最大回撤,并支持参数寻优与滚动样本外验证。
3. 信号触发后 60 秒内推送到手机,消息含:方向、点位区间、置信票源、AI 理由、K 线图。
4. 每个信号自动登记模拟台账,系统能周报命中率与模拟盈亏——**用数据而不是感觉评估系统有效性**。
5. AI 研判作为辅助票存在:任何推送可追溯到"技术票/资金面票/信息票"各自的强度值。

## 4. 范围与边界

**本期做**:数据采集入库、指标与信号引擎、回测与优化、信息挖掘管线、AI 三票研判、模拟台账、推送、Web/H5 看板。

**本期不做**(明确排除,防止方案膨胀):
- 实盘自动下单与资金对接——纸面胜率数据满 3 个月前不碰;
- 日内高频/毫秒级策略——分钟级粒度即符合"买卖点波段"定位;
- 多租户 SaaS、企业权限体系、本地脱敏管线——BitSoul 面向机构企业的能力,个人自用不需要;
- Electron 桌面端——统一做 Web + 响应式 H5;
- 自建大模型或微调——仅调用 API 与多模型路由。

## 5. 设计原则

1. **规则决策,AI 解释与加权**:价格点位永远来自可回测的规则(可追溯、可统计);LLM 不直接输出"明天涨到 X",它负责信息→事件→情绪的结构化理解、K线图的第二意见、以及给信号写理由。理由:LLM 预测无校准、不可回测,这是 BitSoul 的 `check-trade-alerts`(规则触发)与 `recommendations/generate`(AI 生成推荐)分工的启示。
2. **三票合议**:技术票(K线形态/指标交叉)、资金面票(成交量/资金费率/持仓量/爆仓/A股量能)、信息票(事件与情绪)。满足 ≥2 票且总分过阈才推送,推送里逐票展示强度。
3. **一切可度量**:任务化异步计算、全量留痕(信号、推送、模拟成交、复盘标注),评测集即资产。
4. **PIT(point-in-time)纪律**:任何回测与"信息挖掘"只能使用该时间点已存在的数据,杜绝未来函数(借鉴 BitSoul 的 PIT 数据检查)。
5. **供应商可替换**:行情走 ccxt/Tushare 抽象层,LLM 走 OpenAI 兼容网关 + 回退链(借鉴其 model fallback),推送走适配器。

## 6. 总体设计

### 6.1 分层架构

```
┌──────────────────────────  触达层  ──────────────────────────┐
│ Telegram Bot / 钉钉·企微·飞书 webhook / Bark·Pushover        │
│ 信号卡片:方向+点位区间+三票强度+AI理由+K线缩略图              │
├──────────────────────────  应用层  ──────────────────────────┤
│ Web/H5 看板:自选池、K线(lightweight-charts)、信号历史、       │
│ 台账报表、规则编辑器、复盘标注                                │
├────────────────────────── AI 层 ─────────────────────────────┤
│ A1 信息挖掘管线    A2 多模态读图票   A3 策略生成器            │
│ A4 信号解释/文案   A5 个人研判知识库(RAG,发送前自动召回)     │
│ 模型网关:OpenAI 兼容多 provider + 回退列表 + 按任务定价选模   │
├──────────────────────── 信号与研究引擎(核心) ────────────────┤
│ S1 指标计算(pandas-ta/TA-Lib)        S2 规则引擎(JSON DSL)   │
│ S3 调度器(APScheduler,分钟级tick)    S4 回测(vectorbt)        │
│ S5 寻优/稳健性(滚动样本外+压力场景)  S6 模拟台账(paper-ledger)│
├──────────────────────────  数据层  ──────────────────────────┤
│ D1 行情:ccxt(币:K线/深度/资金费率/爆仓)                      │
│ D2 行情:Tushare Pro / AkShare(A股:日线+财务+行业+北向)       │
│ D3 资讯:RSS(Odaily/CoinDesk/TheBlock/东财公告页)、           │
│    另类数据(Fear&Greed、链上/ETF流向,免费档起步)             │
│ D4 存储:ClickHouse 或 DuckDB(行情时序) + PostgreSQL(业务)    │
│    + pgvector / Milvus(知识向量索引) + 对象存储(原文快照)     │
└──────────────────────────────────────────────────────────────┘
```

### 6.2 核心数据流(一条信号的旅程)

```
调度器tick(每分钟/5分钟)
 → 拉最新K线&指标入库 → S2 规则引擎逐条评估自选池
 → 命中技术票 → 并行取 资金面票 + 信息票(A1 最近N条结构化事件的聚合分)
 → 三票合议过阈值? 否→仅入库(可在看板回看"差一点"信号)
                    是→S6 登记模拟持仓 → 生成K线截图
 → A4 用(信号上下文+三票明细+RAG召回的本人历史复盘)写理由,限200字、强制JSON输出
 → 推送适配器发送 → 用户可一键回复"采纳/忽略/看错"标注 → 回流评测集
异常路径:交易所限频→指数退避+多节点轮换;LLM失败→回退模型链;全链失败→降级推送"纯信号无理由"版
```

### 6.3 信号规则 DSL(示例)

```json
{
  "symbol": "BTCUSDT", "timeframe": "4h",
  "entry": {"all": [
    {"cross_up": ["ema20", "ema60"]},
    {"rsi14": {"<": 70}},
    {"funding_rate": {"<": 0.0005}}
  ]},
  "chandelier_exit": {"atr_mult": 3},
  "vote_min": 2, "cooldown_bars": 6, "confidence": 0.6
}
```

## 7. 关键技术选型清单

| 层 | 选型 | 理由 |
|----|------|------|
| 行情采集 | **ccxt**(币,H65+交易所统一API)、tushare pro / akshare(A股) | 免费起步,一套抽象层防供应商锁定 |
| 指标/回测 | pandas-ta、**vectorbt** | 向量化回测个人机即可;需要事件驱动细节再补 backtrader |
| 后端 | Python **FastAPI** + APScheduler + Celery(可选) | 与 BitSoul 同型(FastAPI 风格 API + 任务化异步);团队心智成本最低 |
| 存储 | ClickHouse(或起步期 DuckDB 单文件)/ PostgreSQL / pgvector | 列存扛时序;pgvector 起步够用 |
| 模型层 | 任一 OpenAI 兼容网关:**DeepSeek、Qwen、Kimi、GLM、GPT、Claude** + one-api 类聚合,含回退链 | 借鉴 BitSoul"实时模型列表勾选+模型回退+按账号配额";信息提取用便宜模型,读图/解释用多模态旗舰 |
| 前端 | Next.js/React + Ant Design + **Lightweight-Charts**(TradingView 开源) | 专业K线几十KB,勿自绘canvas |
| 推送 | Telegram Bot(币圈首选)/ 企业微信应用消息 / 飞书 webhook / iOS Bark | 全免费;卡片=文本+图片消息 |
| 抓取 | feedparser(RSS)+ requests/playwright(东财公告/研报列表页) | 参考 BitSoul 双源范式;**预留扫码登录会话管理**(如需公众号源) |
| 部署 | 1 台 2C8G 云主机起步 + Docker Compose | 币 7×24 需要常开;A股收盘任务可省 |

## 8. 与 BitSoul 的借鉴对照(本方案的"站在肩膀上"清单)

| 借鉴 | 移植方式 |
|------|---------|
| 任务化异步计算(创建任务/流式进度/取产物) | Celery队列+SSE,回测/寻优/文档分析全部任务化 |
| 监控规则 + 调度器 + 信号检查分离(rules/check-trade-alerts) | 规则DSL与执行扫描解耦,改规则不断在跑任务 |
| 模拟盘台账 + 成交CSV导入对比 | S6+人工标注回流,构成策略评测集 |
| PIT 数据检查、rolling-window/robustness/stress-scenarios | 回测模块标配样本外滚动+压力场景 |
| 研报/公众号双源抓取+大文档分批喂模型 | 资讯管线复用"抓取→切分→分批提取→入库带提示词" |
| 发送前自动召回知识库 | 复盘笔记/参数结论入向量库,信号解释时自动注入 |
| 多模型路由+回退列表+能力检测(看图) | 模型网关按任务类型选模;读图票仅发给支持视觉的模型 |
| 弃:Electron、多版本智能体广场、企业脱敏、企查查集成、一体机 | 个人场景不需要,砍掉 |

## 9. 实施路径与里程碑

| 阶段 | 周期 | 交付物 | 通过标准 |
|------|------|--------|---------|
| **P0 最小闭环** | 第 1-3 周 | ccxt+Tushare 采集入库;2-3 个均线/波动突破策略;vectorbt 回测报告;调度扫描+Telegram推送(纯规则版,无AI) | 自选池信号真实推送到手机;回测含成本与样本外曲线 |
| **P1 度量闭环** | 第 4-6 周 | 模拟台账、信号标注回流、周度命中率/盈亏比报表;K线截图卡片;A股扩标的 | 能回答"过去两周技术票胜率多少" |
| **P2 智能研判** | 第 7-12 周 | A1 信息挖掘(LLM 结构化输出 schema 化)、三票合议引擎、A4 解释文案、A2 读图票、模型网关+回退 | 推送含三票明细与理由;信息票可独立回测(IC/命中率对照) |
| **P3 知识与生成** | 第 13 周起 | 个人研判知识库 RAG(复盘自动召回)、A3 自然语言→策略草稿→沙箱回测→人审上线 | 新策略从想法到回测报告 ≤1 天 |

里程碑验收点:M1=P0 上线(可演示)、M2=P1(有指标)、M3=P2(三票推送)、M4=P3(知识召回生效)。

## 10. 验收标准

1. 连续 30 天无人值守运行,漏报抽检 <1%(与人工复扫对比);推送触达成功率 >99%。
2. 每类信号可在台账中查看:触发数、采纳数、模拟盈亏、按票源分解的贡献度。
3. 回测可复现:固定随机种子与数据版本,重跑结果一致。
4. 更换行情供应商(币所/数据商)改动不超过采集层适配器;更换 LLM 供应商不改业务代码。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 回测过拟合,实前信号质量崩塌 | 系统性亏损预期 | 参数寻优强制滚动样本外+多标的分散验证;信号先跑 3 个月纸面台账再谈信任 |
| 幸存者偏差(退市币/ST股) | 胜率虚高 | 数据层保留已退市标的与历史名单快照 |
| 交易所/数据 API 限频与封禁 | 推送延迟、采集缺口 | 退避重试+多KEY轮转;关键路径降级(仅日线) |
| LLM 幻觉/注入(资讯含诱导文本) | 错误理由混入推送 | 只做"解释已有信号"不做"决定是否推送";引用溯源(消息附原文链接);敏感字段过滤 |
| **合规红线** | 法律风险 | 境内对虚拟币交易服务受限:本系统定位个人研究工具,不做资金归集、不向他人提供信号服务、不接真实下单API;A股方向对外有偿荐股需投顾牌照——**自用边界内运行**;推送内容标注"研究信号,非投资建议" |
| 单点服务器故障 | 错过行情窗口 | Docker Compose 可 1 小时内重建;信号历史在库,不依赖在线状态 |

## 12. 成本与资源

- 人力:P0-P1 单人全栈可完成(需 Python+Web 基础);P2 起若并行可加 1 名兼职。
- 现金:云主机约 ¥100-200/月;Tushare Pro 积分版 ¥500/年级;LLM API 按 P2 用量估 ¥100-300/月;其余(ccxt/组件/Telegram/akshare)免费。首年 ≤ ¥5000。

## 13. 关键假设与待确认问题

**假设**:①定位个人自用/小团队内部工具(若目标是对客户销售,合规章节需整体重写);②标的以 A股+主流币现货为主,不含美股(可后扩);③分钟级足够,无低延迟诉求。

**待你确认**:
1. 主战场是虚拟币还是 A股优先?(决定 P0 先接哪条数据链)
2. 推送渠道首选 Telegram、飞书/企微还是 iOS Bark?(影响触达模块第一条链路)
3. 是否计划未来做成多用户产品?(若是,权限与脱敏从 P2 就要预留,而不是到时补课)
